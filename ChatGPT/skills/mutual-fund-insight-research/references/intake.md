# Study and update an archive

Use only sources supplied or otherwise authorized by the user. Preserve the installation's established layout and destinations.

1. Discover available issue files across year folders. Compare content hashes with the archive manifest, verify cover dates and exact PDF page counts, and investigate replacements or duplicates. An unavailable folder is an access failure, not an empty archive.
2. Read every page, including covers, images, tables, sidebars, advertisements and supplements. Use full text and rendered page images; zoom charts and image-only disclosures. Extraction is a search aid, not proof of reading. Record unreadable material and actual text/visual review honestly.
3. Create original paraphrased notes under one heading per one-based PDF page. Keep dates, units, qualifications, opinion/ad attribution and unresolved source errors. Preserve available extracted text separately as private source material.
4. Update the manifest, topic index, cross-issue synthesis and coverage audit. Check source and note hashes, sequential page coverage, nonempty notes and duplicate issue identities. Validation checks the records; it does not prove the review happened.
5. Record progress for each configured destination separately: local archive, installed skill, hosted agent and GitHub package. Follow the installation's supported workflow for each. Validate a hosted deployment against its actual library version and a new-issue question before marking it complete.
6. After any validated manual or scheduled skill or research change, refresh the public research principles when lessons change, regenerate the portable package and coverage fingerprints, run privacy/link checks, and sync through the configured publisher. Use an explicit allowlist; keep original PDFs, detailed notes, raw extracts, private workflows, credentials, Site files and personal data out of a public package. Preserve unrelated repository content and reconcile overlapping remote edits.
7. Verify the remote result, record the publication revision and report a failed or unavailable destination as pending. Retry pending destinations even when no new PDF appears. A successful local file write does not establish that a Site or GitHub was updated.
8. Remove only temporary renders, scratch extractions, staging copies, deployment archives and owned preview processes created by this run. Verify resolved absolute targets before recursive deletion. Retain original PDFs, finished research, durable workflow/state files and existing credentials.

When no source, instruction, synthesis or destination changes are pending, a check should create no commit. Scheduling and publication authorization belong to the user's installation; copying this package alone creates neither.
