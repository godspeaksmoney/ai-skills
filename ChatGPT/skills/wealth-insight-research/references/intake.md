# Study and maintain the archive

1. Inspect the user-selected archive for new or changed PDFs. Compare content hashes with the manifest, confirm the cover date and exact PDF page count, and investigate duplicates or replacements before changing an existing entry.
2. Read every page from cover to back cover, including sidebars, advertisements, charts and tables. Use text and rendered pages, with OCR where needed. Verify important labels and figures visually. Write original, searchable notes under one `## PDF p. N` heading per page, preserving dates, units, caveats and promotional attribution. Record unreadable material honestly.
3. Update the issue notes, topic index and manifest together. The manifest should record source and note paths, hashes, PDF page count and actual coverage. Run `node scripts/check-archive.mjs "<research-directory>" ["<originals-root>"]` from this skill directory to verify hashes and that page headings cover the recorded range exactly once. The check verifies the records and files; cover-to-cover reading requires the actual review. Verify that a question about the new issue retrieves its note and original page citation.
4. If a private agent has a configured update path, sync the validated research through it and verify a question specific to the new issue there. Follow the installed project's private publication configuration for its GitHub mirror after a validated issue intake or a change to this skill or its maintained references. Use the configured export list, check the published diff and commit, and report archive, agent and GitHub results separately when a step needs follow-up.
5. Retain the original PDFs and finished research. Remove temporary extraction files, renders and staging files created for the run after verification.

A publication workflow runs when invoked by intake, an authorized skill edit or a configured automation. Follow the user's existing schedule when available. A local file change reaches the mirror after that workflow runs.
