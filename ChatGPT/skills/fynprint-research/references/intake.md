# New-issue intake

Use this procedure for newly supplied issues and for a user-authorized private collection. It works with the user's existing filenames, notes and storage; it does not require a particular host or browser.

## Identify and review

1. Inspect the originals and compare every year/volume with the review inventory and any downstream collection. Check pending records as well as missing issues. Do not infer completeness from the highest issue number.
2. Confirm volume, cover date, issue range and actual PDF page count from the file. Preserve conflicting dates or filenames for resolution. Record the original file's SHA-256 so a later replacement cannot be mistaken for the reviewed copy.
3. Study every page. Render image-only pages, charts and tables; use OCR to aid reading and verify material values, labels, signs, units and footnotes visually. Account for covers, contents, advertisements, visual recaps and teaser-only sections. An extracted-text file alone does not establish complete review.
4. Write original paraphrases with one-based PDF page ranges. Record product variants, reporting/effective dates, return and tax bases, interview attribution, proposal status, numerical inconsistencies and any unverified linked continuation. Compare sources across editions where helpful.

## Save progress before syncing

Save the issue identity, source hash, actual page count, reviewed pages, review date and page-cited notes in the user's designated private records. Keep separate states for complete review, saved notes, updated coverage and each requested downstream destination. A failed upload must not discard a completed review.

Append absent notes while preserving prior editions. Use recoverable or atomic updates where available, then read the saved notes back. Update the private skill's coverage record or its designated coverage source to reflect only completed local reviews. Retrying an older pending issue must not move the latest coverage date or edition backward.

## Verify the requested destinations

Use the configured, authorized access method for a private search collection or agent. Keep secrets out of notes, source, command arguments and schedule prompts. Confirm access independently of source-file availability.

Use a stable year/volume identity. Identical retries should be safe, and differing records should be investigated rather than silently overwritten. After writing, read the stored issue back and compare its full normalized notes and page citations, using a content hash when supported. Check that the edition appears once in the collection and that its citation can be retrieved.

Report the results separately: pages reviewed, notes saved, coverage updated, downstream synchronization verified, and any pending step. Do not report overall completion while a requested destination remains unverified. Preserve pending work for the next run and clean temporary rendering/OCR files after the durable records are safe.

## Optional recurring intake

Create or modify a schedule only when requested. Record the user's time zone, actual source-access method, operating instructions, update path and completion checks. Verify a real update and readback before calling the workflow ready. A local schedule depends on the computer and application being available. Missing issues or unavailable access remain pending work.

For this magazine, use an authorized publisher access or delivery method, or manually supplied copies. Preserve subscription and access boundaries.
